# 做市商模拟器 · Market Maker Academy

面向加密资产做市服务 BD 的日系动漫培训模拟器。原创人物立绘与交易工作室场景，配合客户会谈、方案报价、谈判、模拟交付和带教复盘。当前版本为离线、虚构客户案例的培训首版。

## 运行

需要 Godot 4.7.2。编辑器打开 `bnb/project.godot`，首次等待素材导入后按 F5。Mac 双击 `启动做市商模拟器.command`；原 `启动游戏.command` 同样进入新版本。GL Compatibility 可使用 `启动游戏_兼容模式.command`。

```sh
GODOT_BIN=/Applications/Godot.app/Contents/MacOS/Godot ./启动做市商模拟器.command
```

从 Git 获取资源需先安装 Git LFS，再运行 `git lfs install` 与 `git lfs pull`。旧经营游戏源码和 `scenes/operations.tscn` 保留；本次更改在 `market-maker-bd` 分支。研修存档使用新模式和新应用数据目录，不覆盖旧公司进度。

## 培训流程

1. **需求会谈**：问清验收指标、资金与库存、资产权属、商业预算、交易流和场所覆盖。前三项缺失时不能报价。
2. **方案工坊**：配置价差、每场所每侧 ±1% 深度、客户授权资金、服务费、场所数量与风险方案。双边资金不能重复承诺，保留 20% 示例风险缓冲。
3. **客户谈判**：解释服务边界；不合理价格、交易量或损失兜底承诺需要返工。超预算、覆盖不足或超过目标价差的方案退回修改。
4. **交付观察**：六个训练日逐步处理交易流、价格冲击与接口故障。可以继续报价、放宽价差并再平衡，或暂停核查，同时决定是否通知客户。
5. **带教复盘**：需求、方案、边界、交付与沟通五维练习分，附完整决策记录；导出本地 Markdown 复盘。

三份客户委托：**星见计划**（上市初谈）、**白鲸协议**（多场所扩容）、**月白网络**（极端行情与事故沟通）。

## 模拟定义

- bps 价差 = `(Ask − Bid) / Mid × 10000`；深度在中间价 ±1% 内按每场所、每侧统计。
- 三档订单簿按价格顺序计算加权成交，深度不足只部分成交；可观察 10,000 USDT 示例买入的均价和滑点。
- 客户资产市值 = USDT 余额 + 代币数量 × 中间价。自然交易流与固定情景价格路径只用于教学。
- 成本包含示例交易成本、逆向选择估算和按中间价/3 bps 示例成本再平衡。模型省略真实队列、延迟、隐藏流动性、融资及跨场所转账，不预测实盘收益。
- 月度服务毛利与客户资产盯市变化分开，六个训练日不等同于一个实际服务月。
- 练习分用于带教讨论，不作为公司的正式员工考核或交易收益证明。

## 公司内容配置

## 四渠道课程（2026-10-13）

首页或侧栏“渠道课程”提供 Uniswap、币安 Alpha、交易所现货和交易所合约四课。每课包含四个机制主题、客户访谈清单、交互计算实验、四道有解释的情景题及本地复盘导出。原有三个现货客户案例仍保留。

- Uniswap：v2/v3/v4 机制差异、固定集中流动性区间、相对持币价值变化、链与池/hook 身份核对。实验使用精度归一的基本集中流动性公式，不含 ticks、费用、gas 或 hook 自定义逻辑。
- 币安 Alpha：钱包/Alpha 2.0/正式现货区别、订单类型与接收保护、成本和状态核对，不保证上市、活动资格或奖励。实验仅为通用数量保护示意，不复制平台扣费或撮合算法。
- 现货：三档订单簿的有限深度、加权成交均价和滑点；完整会谈、报价及六日交付继续使用主页案例。
- 合约：合约规格、资金费方向、标记价、保证金模式和对冲风险。实验只为单仓 USDT 线性永续、固定 MMR 的结算快照，不是完整强平引擎；币本位、交割与全仓组合不使用此计算器。

课程内容与参考链接在 `bnb/data/mm_bd_channels_v1.json`（Godot 项目内 `data/mm_bd_channels_v1.json`），机制核对日期为 2026-10-13；平台政策变更需要再次核验。每题首次回答计入本轮，新一轮保留旧记录；成绩用于带教讨论。渠道回答自动写入独立的 `user://mm_bd_channels_v1_<规则哈希>.json`，每次提交验证临时档并保留备份，异常文件不会覆盖。原会谈档及数据未改动。

新增回归脚本：`mm_bd_channels_runner.gd` 验证计算、评分、重启恢复与坏档保护；`mm_bd_channels_ui_runner.gd` 验证课程入口、参数交互、16 题答题/导出与 1200×720 布局。

## 三渠道完整客户委托

侧栏“客户委托”、主页“完整客户委托”或渠道课程里的“进入完整客户委托”均可进入新增三案。每案要完成六项访谈、独立报价、三轮客户异议、六日交付及五维复盘。原有三份现货委托和四渠道机制测验保留。

- 风铃协议 / Uniswap v3：配置区间半宽、LP 与现金储备、gas 上限；交付观察原两币资产、出区间、重设成本、费用估算和链异常。暂停冻结新调整，原 LP 风险仍在。v4/hooks 需要另行审查，此案不把基本 v3 模型扩称为所有池。
- 琉光计划 / Alpha：配置单笔、每日额度、接收容忍度、储备和网络预算；观察待确认锁定、确认到账、薄池、身份不一致与成本异常。模拟通用授权执行与渠道沟通，不声称公司能直接控制 Alpha 撮合、API 或上市资格。
- 白露资本 / 合约：配置报价价差、名义深度、现货/保证金分配、对冲比例和杠杆上限；真实记录本沙盘的合约成交、平均入场、实现/未实现损益、净敞口、单次资金费及压力关闭成本。暂停报价不消除原合约仓位。

配置：`bnb/data/mm_bd_mandates_v1.json`，其中 `simulation` 集中放置固定教学费率、维持保证金率与资金缓冲。原现货和机制课配置文件未改动。新委托用独立 `user://mm_bd_mandates_v1_<规则哈希>.json`，每项操作经重放验证后自动保存，损坏档不会覆盖；草稿可用“保存委托”保存，读取/恢复按页面操作对应委托档。重新启动自动打开已保存的新委托。训练记录中合并展示两个系列的完成记录。

完整复盘导出需求、报价、三轮谈判、逐日资金/成本/授权处置和模型边界。训练步数不代表真实月度利润；客户资金损益和月度服务毛利独立计量。所有产品规则按课程内官方参考复核，正式培训需公司 SOP 校准。

新回归：`mm_bd_mandate_runner.gd` 和 `mm_bd_mandate_ui_runner.gd`。本地打包：`python tools/package_mm_bd.py --edition full-flow`，输出新完整流程版，原试玩包保留。
