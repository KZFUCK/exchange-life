# BD 研修操作

默认场景是 `scenes/mm_bd.tscn`。研修主页选择客户委托，通过问题了解需求，再在方案工坊输入报价与风险范围。必需访谈项是验收指标、资金安排和服务边界。

客户提出不合理承诺时，需解释真实流动性服务的交付指标。超出预算或覆盖不足的方案会回到工坊；保证价格、成交量和损失的回答不会进入交付。

交付观察台每个训练日需要选择处置建议，底部三个按钮固定可见。注意中间价、双边深度、试单滑点与库存；按勾选项决定是否向客户说明影响与恢复条件。

六日后进入带教复盘，可导出报告。保存、读取和恢复备份在右上角，读取与恢复需要确认，取消保留当前状态。关闭窗口会保存，重开会继续有效研修档；坏档受保护。

当前是虚构案例的培训首版，公司真实服务政策需由负责人核对。旧经营源码、模型和独立存档保留作为回退。

## 四渠道课程（2026-10-13）

首页或侧栏“渠道课程”提供 Uniswap、币安 Alpha、交易所现货和交易所合约四课。每课包含四个机制主题、客户访谈清单、交互计算实验、四道有解释的情景题及本地复盘导出。原有三个现货客户案例仍保留。

- Uniswap：v2/v3/v4 机制差异、固定集中流动性区间、相对持币价值变化、链与池/hook 身份核对。实验使用精度归一的基本集中流动性公式，不含 ticks、费用、gas 或 hook 自定义逻辑。
- 币安 Alpha：钱包/Alpha 2.0/正式现货区别、订单类型与接收保护、成本和状态核对，不保证上市、活动资格或奖励。实验仅为通用数量保护示意，不复制平台扣费或撮合算法。
- 现货：三档订单簿的有限深度、加权成交均价和滑点；完整会谈、报价及六日交付继续使用主页案例。
- 合约：合约规格、资金费方向、标记价、保证金模式和对冲风险。实验只为单仓 USDT 线性永续、固定 MMR 的结算快照，不是完整强平引擎；币本位、交割与全仓组合不使用此计算器。

课程内容与参考链接在 `bnb/data/mm_bd_channels_v1.json`（Godot 项目内 `data/mm_bd_channels_v1.json`），机制核对日期为 2026-10-13；平台政策变更需要再次核验。每题首次回答计入本轮，新一轮保留旧记录；成绩用于带教讨论。渠道回答自动写入独立的 `user://mm_bd_channels_v1_<规则哈希>.json`，每次提交验证临时档并保留备份，异常文件不会覆盖。原会谈档及数据未改动。

新增回归脚本：`mm_bd_channels_runner.gd` 验证计算、评分、重启恢复与坏档保护；`mm_bd_channels_ui_runner.gd` 验证课程入口、参数交互、16 题答题/导出与 1200×720 布局。
